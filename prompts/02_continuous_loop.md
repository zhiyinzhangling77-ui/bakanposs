# プロンプト 02 — 自走ループ本体（`/loop` に貼る）

> 使い方: 研究セッションで `/loop ` に続けて以下の `---` 内をそのまま貼る。
> 間隔は指定しない（Claude が自分でペースを決める）。

---

`docs/LOOP_STATE.md` → `docs/LOOP_QUEUE.md` → `docs/HUMAN_GATES.md` を毎周の冒頭に読み、研究を自走で進めてください。

## 大原則 — 状態はディスクに置く。コンテキストは揮発するものとして扱う

**あなたのコンテキストはいつ消えてもおかしくない。** 会話履歴を記憶装置として使わないこと。

- 得た情報は**その場で**該当ファイルに書く。「あとでまとめて書く」は禁止
- 進捗の真実は `docs/LOOP_QUEUE.md`、現在地の真実は `docs/LOOP_STATE.md`。会話は真実ではない
- **1 周 = 1 コミット + push。** これによりコンテキスト消失で失うのは最大 1 周分に限定される
- 周の途中で終わらない。**始めた項目は完結させてからコミットする**（できないなら `LOOP_STATE.md` の「進行中の作業」に行番号つきで書き残す）

## 最重要ルール — 止まるタイミング

**最初のブロッカーで止まらないこと。**

私の手が必要な作業に当たったら、そこで停止せず:
1. `docs/HUMAN_GATES.md` に `GATE-xx` として登録（`prompts/01_human_gate_audit.md` Step 4 の 9 項目を埋める）
2. `docs/LOOP_QUEUE.md` の該当項目を `BLOCKED(GATE-xx)` に変更
3. **キューの次の項目へ進む**

**停止するのは「残っている項目が全部 BLOCKED になった時」だけ。** その時に初めて `stop` し、未解決 GATE の全リストを出力する。

## 各周でやること

```
1. 状態復元    LOOP_STATE.md → LOOP_QUEUE.md → HUMAN_GATES.md
2. ガードレール SESSION_SUMMARY.md §10.3 (禁止14項) と §10.4 (不変条件) を読み直す
3. 選択        LOOP_QUEUE.md から BLOCKED でない最優先項目を 1 つ → status: DOING に更新してコミット
4. 実行        完了まで一気にやる。中途半端に次へ移らない
5. 検証        - Python は構文チェック + 実データ不要な部分の単体実行
               - 数値を引用したら SESSION_SUMMARY のどこ由来か明記
               - 自分の diff を敵対的に読み直す
6. 記録        - LOOP_QUEUE.md を DONE に + 完了ログに 1 行追記
               - SESSION_SUMMARY.md の §6/§7/§8 に反映
               - LOOP_STATE.md を更新（6 項目すべて）
               - git add -A && git commit && git push -u origin <このブランチ>
7. コンテキスト残量を確認 → 下記プロトコルへ
8. 次周へ
```

## コンテキスト上限プロトコル

毎周の **Step 7** で残量を見積もり、以下に従う。

| 残量 | 行動 |
|---|---|
| **十分** | そのまま次周へ |
| **半分を切った** | **重い項目を新規に開始しない**。軽い項目（文章・索引・小さな修正）だけを選ぶ。大きなファイルの全文読みをやめ、`sed -n` の部分読みに切り替える |
| **残り僅か（次の周を完走できない見込み）** | **引き継ぎ書き出しを実行して停止**（下記） |

### 引き継ぎ書き出し（残量が尽きる前に必ず行う）

1. 進行中の作業を**キリのいいところまで**完結させる。無理なら、その時点の状態を `LOOP_STATE.md`「進行中の作業」に**行番号つきで**書く
2. コンテキスト内にしかない情報を**すべて**ファイルへ移す（数値・判断・気づき・失敗した試行）
   - 失敗した試行は `SESSION_SUMMARY.md §4`（失敗した手法と理由）へ。**これを書き残さないと次のあなたが同じ失敗を繰り返す**
3. `LOOP_STATE.md` の 6 項目を更新。「次に取るべき項目」は**具体的なファイル名と行番号**で書く
4. コミット + push
5. 私にこう伝えて停止:
   > コンテキスト上限が近いため引き継ぎを書き出して停止しました。新しいセッションで `prompts/00_cold_start.md` の内容を貼れば、そのまま続きから再開できます。

**この手順を踏まずにコンテキストが尽きるのが最悪のケース。** 余裕を持って早めに実行すること。

### コンテキストの節約（常時）

- `SESSION_SUMMARY.md` は 36 KB ある。**全文を読まない。** `grep -n '^#\{1,3\} ' SESSION_SUMMARY.md` で節の行番号を引き、必要な節だけ `sed -n 'X,Yp'` で読む
- 大きなログ・CSV は全文を読まず `head` / `grep` / 集計して読む
- 一度読んで理解した内容は、**要約をファイルに書いてから忘れる**前提で扱う
- 探索的な調べもの（多数のファイルを横断する調査）は、可能ならサブエージェントに投げて**結論だけ受け取る**

## 絶対にやってはいけないこと（研究の誠実性）

1. **数値の捏造・推測での穴埋め。** 実データを走らせないと出ない値を「たぶんこのくらい」で書くのは、この研究を破壊する行為。分からないなら BLOCKED にする
2. **プレースホルダを本文に残したまま DONE にする。** `TBD` を書いたらその項目は DONE ではなく BLOCKED
3. `SESSION_SUMMARY.md §10.3` の 14 項目（特に **13: deep-root 肯定記述**、**14: main への直接 push**、**12: 生 CSV の git add**）
4. **GATE を「自分で何とかする」ために迂回すること。** 認証が要るなら要る、実データが要るなら要る、と正直に止める
5. `§1.4 仮説の変遷` と `§1.5 不変条件` の書き換え
6. 私に確認せずに PR を作る／マージする
7. **記憶が曖昧な状態で既存ファイルを上書きすること。** 迷ったら `git diff` と `cat` で現物を確認してから触る

## 進め方の優先順位

`SESSION_SUMMARY.md §7` の優先度に従いつつ、同順位内では**「GATE を増やさない作業」を先に**やる。
AUTO 作業を先に食い潰し、私が席に着いたとき **1 回のローカル実行セッションで最大数の GATE が片付く状態**を作ってから止まること。

## 停止時の報告フォーマット

```markdown
## 自走ループ完了 — あなたの手が必要です

### 今回進んだもの（N 件）
| 項目 | 内容 | コミット |

### 止まった理由
残り M 件すべてが人間待ち／コンテキスト上限

### あなたにお願いすること（所要 約X分）
#### バッチ1: ローカル実行（まとめて 1 回）
GATE-01, GATE-03, GATE-05
```bash
<コピペで動くコマンド列>
```
→ 返してほしいもの: <具体的に>

#### バッチ2: 判断（PC 不要・この場で答えられる）
GATE-12: <選択肢A> か <選択肢B> か。私の推奨は <> 、理由は <>。

### これが解けると次に動くもの
GATE-04 → Q07, Q15（C レポート §8.6/8.7）

### 再開方法
このセッションが続いていれば結果を貼るだけ。
セッションが切れていたら `prompts/00_cold_start.md` を新セッションに貼る。
```

## 再開

私が結果を貼ったら、該当 GATE を `status: resolved` にして `LOOP_QUEUE.md` を更新し、**ループを再開**すること（再度 `/loop` を打たせずに、その周のうちに次の AUTO 作業へ進む）。
