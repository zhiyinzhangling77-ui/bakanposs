# プロンプト 00 — コールドスタート（記憶ゼロからの再開）

> **使う場面**: コンテキストが上限に達した／セッションが切れた／別のセッションで続きをやる。
> 新しいセッションを開いて、以下の `---` 内をそのまま貼る。**これ以外に何も説明しなくてよい設計**になっている。

---

あなたはこのリポジトリで進行中の研究を、自走ループで引き継ぎます。**あなたには一切の会話履歴がありません。** 状態はすべてファイルに書かれています。

## Step 1 — 状態の復元（この順番で読む。順番に意味がある）

```bash
cat docs/LOOP_STATE.md          # 1. 今どこにいるか（最重要・唯一の再開ポインタ）
cat docs/LOOP_QUEUE.md          # 2. 何が残っているか
cat docs/HUMAN_GATES.md         # 3. 何が人間待ちか
sed -n '/## 10\./,$p' SESSION_SUMMARY.md   # 4. 禁止事項と不変条件
git log --oneline -15           # 5. 直近の実作業
```

`SESSION_SUMMARY.md` は全文 36 KB あります。**最初から全部読まないこと**（それ自体がコンテキストを食う）。
まず `§10`（次セッション用コンテキスト）だけ読み、必要になった節を都度 `sed -n 'X,Yp'` で読むこと。節の行番号は `grep -n '^#\{1,3\} ' SESSION_SUMMARY.md` で引けます。

## Step 2 — 整合性チェック（引き継ぎ事故の検出）

読み終えたら、以下を確認して**食い違いがあれば作業を始める前に報告**してください:

- [ ] `LOOP_STATE.md` の「最終コミット」と `git log` の HEAD が一致するか
- [ ] `LOOP_STATE.md` の「進行中の作業」が空か（**空でなければ、前の周が中断されている** → まずそれを完結させる）
- [ ] `LOOP_STATE.md` の「まだファイルに書いていない情報」が空か（**空でなければ、そこに書かれた情報を該当ファイルへ移してからコミット**）
- [ ] `git status` がクリーンか（未コミットの変更＝前の周の中断の痕跡。diff を読んで、完結させるか捨てるか判断）
- [ ] `LOOP_QUEUE.md` に `DOING` の項目が残っていないか（残っていればそれが中断された作業）

## Step 3 — ループ再開

整合性が取れたら `prompts/02_continuous_loop.md` の内容に従ってループを続けてください。
（このセッションでも自走させるなら、`/loop` に `prompts/02_continuous_loop.md` の `---` 以降を貼る）

## やってはいけないこと

- **私に「何をしていましたか？」と聞かない。** 答えは `docs/LOOP_STATE.md` にあります。聞かれること自体が引き継ぎ設計の失敗です
- **記憶がないことを理由に最初からやり直さない。** `LOOP_QUEUE.md` の `DONE` は完了済みです
- **中断された作業を「たぶんこうだった」で補完しない。** `git diff` で実際に何が書かれているかを確認すること
