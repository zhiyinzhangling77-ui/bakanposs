# 自走ループ運用キット

**目的**: 研究セッションで Claude を自走させ、**あなたの手が必要になったときだけ止める**。
そして**コンテキストが飛んでも同じ場所から再開できる**ようにする。

## ファイル構成

| ファイル | 役割 | 誰が書くか |
|---|---|---|
| `prompts/00_cold_start.md` | 記憶ゼロからの再開手順 | 固定（貼るだけ） |
| `prompts/01_human_gate_audit.md` | 「手が必要な箇所を洗いざらい出す」プロンプト | 固定（貼るだけ） |
| `prompts/02_continuous_loop.md` | 自走ループ本体 | 固定（貼るだけ） |
| `docs/HUMAN_GATES.md` | 人間待ち項目の台帳（GATE-01〜） | Claude が更新 |
| `docs/LOOP_QUEUE.md` | 作業キュー（Q01〜、進捗の真実） | Claude が毎周更新 |
| `docs/LOOP_STATE.md` | 現在地（再開ポインタ、唯一の真実） | Claude が毎周更新 |

## 使い方

### 初回
```
1. 研究セッションで  prompts/01_human_gate_audit.md  の --- 以降を貼る
   → docs/HUMAN_GATES.md が検証・追補される（初版は静的抽出済み）

2. /loop  に続けて  prompts/02_continuous_loop.md  の --- 以降を貼る
   → 自走開始
```

### 止まったら
Claude が「バッチ1: ローカル実行 / バッチ2: 判断」の形でお願いを出す。
片付けて結果を貼れば、そのまま自動で再開する（`/loop` を打ち直す必要はない）。

**PC もデータも要らない GATE（12, 13, 14, 15, 16）が 5 件ある。** これを先に答えると自走可能な範囲が大きく広がる。

### コンテキストが飛んだら／セッションが切れたら
```
新しいセッションを開いて  prompts/00_cold_start.md  の --- 以降を貼るだけ。
```
それ以外の説明は不要。状態は全部 `docs/` の 3 ファイルに書かれている。

## 設計の中身（なぜこうなっているか）

### 1. 最初のブロッカーで止まらない
素朴に作ると「実データが要る」で 1 分後に止まる。
そうならないよう、ブロッカーは**台帳に登録して迂回**し、**残り全部が BLOCKED になった時だけ**停止する。
これが「手を加える必要があるときだけ止まる」の正しい実装。

### 2. あなたが席に着く回数を最小化する
GATE をバッチ化し、「1 回のローカル実行で最大数の GATE が片付く状態」を作ってから止まる。
`docs/HUMAN_GATES.md` のバッチ表 B1–B5 がその設計。

### 3. コンテキストは揮発する前提で設計してある
- **状態はすべてディスク**。会話履歴を記憶装置にしない
- **1 周 = 1 コミット + push**。消失で失うのは最大 1 周分
- **残量が尽きる前に引き継ぎ書き出し**（`02` のコンテキスト上限プロトコル）
- **失敗した試行を `SESSION_SUMMARY §4` に残す**。これがないと次の Claude が同じ失敗を繰り返す
- `SESSION_SUMMARY.md` は 36 KB あるので**全文を読ませない**（節ごとの部分読みを指示済み）

### 4. 研究の誠実性を最優先にしてある
自走ループの最大のリスクは、**止まりたくないあまり数値を推測で埋めること**。
`02` で最上位の禁止事項として明記し、「分からないなら BLOCKED にする」を徹底させている。
`SESSION_SUMMARY §10.3` の禁止 14 項も毎周読み直させる。
