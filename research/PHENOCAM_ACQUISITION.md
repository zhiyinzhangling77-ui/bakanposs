# 取得指示：**PhenoCam の日次緑度（GCC）**——旗93 が測れなかったものを測るために

**旗93 で「この観測構成では測れない」と確定した**ので、**観測を足す**。
これは旗79（AmeriFlux 26 タワー）と同じ形の一手である。

## なぜ PhenoCam なのか（**NEE では駄目だった理由**）

| | 日ごとに使えるか | タワーの γLE の原因か | 判定 |
|---|---|---|---|
| **NEE**（旗93 で使おうとした） | **使えない**——θ→気孔→蒸散/光合成 の経路上にあり、**日ごとに条件付けると測る関係を歪める** | **一部そうである**（同じ気孔を通る） | **年ラベルに逃げたら対比が足りず失敗** |
| **GPP / LAI** | — | — | **分割派生量**（旗32）＝この研究では使わない |
| **PhenoCam GCC** | **使える** | **違う**——カメラの色は γLE の結果ではない | **これを取る** |

**決定的な違い**：GCC は **γLE の原因でも結果でもない**。
だから**日ごとに層別しても、θ と γLE の関係を人工的に作らない**。
＝**旗93 を潰した「年ラベルの弱い対比」を回避できる。**

**検出力の見積もり**（旗89 の実測から）：US-Wkg の θ高×Rg高 の春は **596 日／18 年**。
**日次 GCC で中央値 2 分 → 各群 ≈ 300 日 → θ の重なり帯で 8 割残るとして ≈ 240 日**
＝**下限 60 日の 4 倍**。**旗93 の 51/35/37 日とは桁が違う。**

## 取得の手順

1. `https://phenocam.nau.edu/webcam/network/table/` で **kendall・luckyhills**、
   および **Santa Rita 系の名前**（`santarita` 等）を探す。**見つかった名前を控える。**
2. 各サイトページから **1-day GCC 要約ファイル（csv）** を、**ROI ごとに全部**取る。
   **3-day ではなく 1-day を採る**——**日次でなければ旗93 の問題が解けない**。
   **ROI が複数あるときは全部取る**（どれを使うかは**下調べ（旗94）の後に人が決める**）。
3. 置き場所：**`/mnt/hdd/PhenoCam/`**（サイトごとの下位フォルダで構わない）。
4. **リポジトリには入れない。** 生データは `/mnt/hdd` に置く
   （`Team_Contacts_for_Site_Data` と同じ扱い。個人情報ではないが、**再配布条件が不明なため**）。

## 取得後にやること

**いきなり検定しない。** **まず下調べ**（旗68/76/79/83/87 と同じ作法）：

```bash
python research/phenocam_probe_step94.py --phenocam-dir /mnt/hdd/PhenoCam
```

**下調べが答えるべきこと**：
- どのサイト・どの ROI が在るか、**列名と日付の範囲**
- **フラックスの年と何年重なるか**（3 年未満なら判定しない）
- **θ高×Rg高 の春に GCC が何日あるか**（下限 60 日を超えるか）
- **GCC と θ が分離できるか**——**緑の日と枯れた日で θ の重なり帯が作れるか**
  （**作れなければ旗93 と同じ壁**＝「水と緑は切り離せない」と確定して終える）

**下調べを通ってから、事前登録（旗95）を書いて検定する。** 順序を変えない。

## 先に認めておく限界

- **PhenoCam の視野はタワーのフェッチと同じではない**——**カメラが見ている範囲と、
  フラックスが積分している範囲は違う**。旗81 で見た「チャンバーの空間代表性」と同型の問題である。
- **GCC は色であって光合成ではない。** 「緑である」と「同化している」は別である。
- **危険①（緑と湿りの絡み）は消えない**——**θ の重なり帯は引き続き必要**。
  **衛星でも同じ**（緑度は雨に応答する）。**GCC で解けるのは危険②（コライダー）だけ**である。
- **US-SRM が無ければ独立クラスタは 1 つ**になる。**そう書く。**
