## 合成検証で分かったこと：**主検定は「VPD で説明された」を出しすぎる**

四つ（＋重なりを広げた検証用）を作って通した結果：

| 合成 | 判定 | 期待どおりか |
|---|---|---|
| `vpd`（現実的な季節振幅） | **帯なし＝判定しない** | ○（**実データへの予測でもある**） |
| `collinear`（VPD ≒ Rg） | **門②が発火** | ○ |
| `vpd_overlap`（VPD が低い日だけ反転） | **explained** | ○ |
| `season_overlap`（秋だけ反転） | **not_explained** | ○ |
| **`wet_overlap`（θ が高い日だけ反転・VPD は無関係）** | **explained** | **△——「VPD で説明された」と出てしまう** |

**`wet_overlap` では、反転を決めているのは θ であって VPD ではない。**
それでも**帯の中で春も秋も反転する**ため、主検定は **explained** を返す。
＝**主検定が答えているのは「VPD を揃えると春秋の差が消えるか」だけ**で、
**「VPD が効いているか」ではない。** **後者を答える検定を足す。**

（帯の中の θ 中央値は 0.233 対 0.223 と**揃っていた**ので、
**「θ が不均衡だから」という既存の印では捕まらない**。**別の検定が要る。**）

## 足す副検定：**春の中だけで VPD を高低に分け、θ を揃えて比べる**

**秋を使わない。** **春の日だけで、VPD が低い日と高い日を比べる。**
**これは機構の主張そのものである**——「**春は高 VPD で気孔が閉じるから反転しない**」なら、
**春の中の低 VPD 日では反転するはず**である。

### 手順（先に固定する）
1. **θ高×Rg高 の春**を、**VPD の中央値**で**低 VPD 群／高 VPD 群**に分ける。
2. **両群の θ の 10/90 パーセンタイルの重なり帯**で絞る（**旗90/95 と同一の作り方**）
   ——**「低 VPD 日は湿った日」という交絡を潰すため**。
3. **帯の中で両群を別々に検定**（統計量は旗31/36/89/90/91/95/96 と同一）。
4. **帯の中の VPD・θ・Rg・Ts の中央値を両群で併記する。**

### 判定規則（先に決める）
| 結果 | 読み |
|---|---|
| **低 VPD 群だけ反転** | **VPD が効いている**——主検定の explained を**支持する** |
| **両群とも反転** | **VPD は効いていない**（春でも反転する日がある）——**主検定の explained は VPD の手柄ではない** |
| **両群とも反転しない** | **春では、VPD を下げても反転しない**——**主検定の explained は帯の取り方の産物を疑う** |
| **高 VPD 群だけ反転** | **想定と逆**。**そのまま記し、解釈しない** |
| θ の帯が作れない／下限未満 | **判定しない**（**低 VPD と湿りが分離できない**と明記） |

### **主検定と副検定の関係**（先に決める）
- **主検定＝事前登録どおりの判定を出す。**（**後から差し替えない**）
- **副検定は、主検定が `explained` を返したときに、それが VPD の手柄かを確かめる。**
- **食い違ったら、両方を書く。** **「VPD で説明された」と断定しない。**
