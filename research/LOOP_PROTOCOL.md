# 自走ループ規約 — **あなたの手が要るときだけ止まる**

**対象**: このリポジトリの研究（`japanflux_pn` / 旗方式）。
**使い方（2 通り）**:
- **無人で回す（推奨）**: `research/run_loop.sh` を使う。**1 周ごとに別プロセスで起動するので文脈が枯渇しない。**
  実データのあるマシンで回せば D 分類のゲートも外れる。→ `research/RUN_LOOP.md`
- **対話で回す**: `/loop` に続けて本書の `## ループ本体` 以降をそのまま貼る（間隔は指定しない）。
**前提**: 実データは `/mnt/hdd`（コンテナ外）。**コンテナでできるのは道具作りと文章だけ**。

> **⚠ 訂正（旗103・2026-09-02）**: 本書は当初「コンテナでできるのは**合成検証**と道具作りと文章」と書いていたが、
> **実際のコンテナでは Python を実行できない**（`python3 --version` は通るが、スクリプト実行と `python3 -c` は
> 承認待ちになり、非対話セッションでは承認を得られない）。**＝合成検証もコンテナではできない。**
> **道具を書いた周は「書いたが未検証」と正直に書き、合成の実行を「データ不要・数分」のゲートとして登録すること**
> （例：GATE-17）。**走らせていない合成を「確かめた」と書くのが最悪である。**

## この規約が足すもの（既存の規律に足りていなかった 3 点）

この研究には既に旗・事前登録・門①②・道具の欠陥番号・予測の勝敗という強い規律がある。
**本書はそれを置き換えない。** 足りていなかったのは次の 3 点だけである。

1. **止まり方の規則がない** — 「ローカル実行が要る」と分かった時点で止まると、
   **手元でできる作業が残っていても止まってしまう**。
2. **人手が要る箇所の台帳がない** — 依頼が旗ごとに散っており（`RUN_HEAVY.md`・各旗の末尾・
   `LITERATURE_VERIFICATION_TODO.md`・`CONTACT_DRAFT_TKY.md`）、
   **「今あなたに何を頼めば最も進むか」が一覧できない**。→ `HUMAN_GATES.md` を新設。
3. **コンテキストが尽きるときの作法がない** — `SESSION_STATE.md` は再開用に書かれているが、
   **いつ・何を書き出してから終わるか**の規則がない。現に本書作成時点で
   **`SESSION_STATE.md` は旗99 止まり・`FLAGS_LOG.md` は旗102**（3 旗ぶん古い）。

## ループ本体

`research/SESSION_STATE.md` → `research/HUMAN_GATES.md` → `research/OPEN_QUESTIONS_OPTIONS.md`
を毎周の冒頭に読み、研究を自走で進めてください。

### 大原則 — 状態はディスクに置く。コンテキストは揮発する

**あなたのコンテキストはいつ消えてもおかしくない。会話履歴を記憶装置として使わないこと。**

- 進捗の真実は `FLAGS_LOG.md`、現在地の真実は `SESSION_STATE.md`。会話は真実ではない
- **1 旗 = 1 コミット + push**（既存の運用どおり）。これで消失時に失うのは最大 1 旗ぶん
- 得た数値・気づき・**失敗した試行**はその場でファイルへ。「あとでまとめて書く」は禁止
- **`SESSION_STATE.md` を更新せずに旗を閉じない。** 本書作成時点で 3 旗ぶん古いのは、この規則が無かったため

### 最重要 — 止まるタイミング

**最初のブロッカーで止まらないこと。**

あなたの手（＝ユーザーの手）が要る作業に当たったら、そこで停止せず:

1. `research/HUMAN_GATES.md` に `GATE-xx` として登録（下記 9 項目を埋める）
2. その作業を `BLOCKED(GATE-xx)` として記録
3. **手元でできる次の作業へ進む**

**停止するのは「残りが全部 BLOCKED になった時」だけ。** その時に初めて `stop` し、未解決 GATE を**バッチにまとめて**出す。

### GATE 登録時に埋める 9 項目

1. **ID** `GATE-xx` / 2. **タイトル** / 3. **分類** D(実行)・A(取得)・P(外界)・J(判断)・S(仕様)
4. **なぜ私にできないか** — **能力・権限・到達性の境界**として 1 行で。「面倒だから」は不可
5. **あなたが打つコマンド／取る行動** — コピペで動く形。パスは `/mnt/hdd` の実パス
6. **返してほしいもの** — ログ全文／特定の数値／yes-no／ファイル、を具体的に
7. **解けると何が動くか** — 旗番号・手 A〜F・GATE 番号で
8. **所要の見積り** / 9. **迂回可能性** — 保留したまま進める作業があるか

### 各周（＝1 旗）でやること

```
1. 状態復元    SESSION_STATE.md → HUMAN_GATES.md → OPEN_QUESTIONS_OPTIONS.md
2. 選択        BLOCKED でない最優先の手を 1 つ
3. 前提の確認  ★旗97 で足した作法：事前登録の前に、前提にする事実を分布で確かめ、その節を設ける
4. 事前登録    PREREGISTRATION_stepNN.md を書く（判定規則・門①対照・下限を先に決める）
5. 道具        合成データで帰無を較正し、全分岐が動くことを確認してから実データへ
6. 実行        手元でできる範囲を完遂。実データが要るなら GATE 登録して次へ
7. 記録        FLAGS_LOG.md に旗を追記 / SESSION_STATE.md を更新 / 道具の欠陥は番号を継いで記録
8. コミット    git add -A && git commit && git push -u origin claude/new-branch-creation-heq0i1
9. 残量確認    下記プロトコルへ
```

### コンテキスト上限プロトコル

毎周の **9** で残量を見積もる。

| 残量 | 行動 |
|---|---|
| 十分 | 次の旗へ |
| 半分を切った | **重い旗を新規に開始しない**。文章・記録の整理・小さな道具に切り替える。`FLAGS_LOG.md`(4000行超) の全文読みをやめ、`grep -n '^## 旗' → sed -n 'X,Yp'` の部分読みに徹する |
| 残り僅か | **引き継ぎ書き出しをして停止**（下記） |

**引き継ぎ書き出し**

1. 進行中の旗をキリのいいところまで閉じる。無理なら `SESSION_STATE.md` に
   **「旗NN の何をどこまで書いたか」を行番号つきで**書く
2. **コンテキスト内にしかない情報を全部ファイルへ移す**。特に:
   - **失敗した試行と、失敗した理由**（これを落とすと次のあなたが同じ失敗を繰り返す。
     旗96・97 の「前提を分布で確かめずに設計に入った」がまさにこの類の損失である）
   - **道具の欠陥**（現在 #34 まで。番号を継ぐ）
   - **予測の勝敗**（現在 7 回中 2 勝）
3. `SESSION_STATE.md` の表題と本文を**最新の旗番号まで**更新する
4. コミット + push
5. こう伝えて停止:
   > コンテキスト上限が近いため引き継ぎを書き出して停止しました。
   > 新しいセッションで `research/COLD_START.md` を貼れば続きから再開できます。

**この手順を踏まずにコンテキストが尽きるのが最悪のケース。余裕を持って早めに実行すること。**

### 絶対にやってはいけないこと

1. **数値の捏造・推測での穴埋め。** 実データを走らせないと出ない値を「たぶんこのくらい」で書くのは、
   この研究を破壊する行為。**分からないなら GATE にする**
2. **事前登録の判定規則を、結果を見てから変えること。**
   旗102 で「下限 3 本は低すぎた」と分かっても規則を変えなかった作法を守る
   （**変えるのは次の事前登録から**）
3. **門①（対照）を省くこと。** 旗96 で MN-Hst は門①で落ちた。門が無ければ結果として数えていた
4. **集計としてしか言えないものをサイトごとに述べること**（旗81：1 本で多数派と一致する確率 83%）
5. **n=1・後付けの観察を主張に上げること**（US-Whs の扱い）。**記録はする、主張はしない**
6. **★選択バイアス（旗85）を忘れて率を語ること**。無作為なら 25〜29%、取得群は 42〜50%
7. **一次文献を確認したことにすること**（旗92：この環境では構造的に不可能・計 8 ホスト遮断）
8. **`MEASURED_ONLY_SPINE.md` の土俵分けを勝手に動かすこと**（骨格の正）
9. **私に確認せずに PR を作る／マージする**
10. **記憶が曖昧な状態で既存ファイルを上書きすること。** `git diff` と現物確認を先に

### 進め方の優先順位

`OPEN_QUESTIONS_OPTIONS.md` の順（手 A → D → C → B → E → F）を基本としつつ、
同順位では**「GATE を増やさない作業」を先に**やる。
**手元でできる作業を先に食い潰し、あなたが席に着いたとき
1 回のローカル実行セッションで最大数の GATE が片付く状態を作ってから止まること。**

### 再開方法

### 再開

私が結果を貼ったら、該当 GATE を `status: resolved` にし、`SESSION_STATE.md` を更新して、
**その周のうちに次の作業へ進む**（`/loop` を打ち直させない）。
